# Pinned to what the SERVER actually runs, verified with `pip list` on 2026-09-05.
#
# 🚨 DO NOT use repo/v2/requirements.txt for this. That file is upstream's and is stale on every
# line that matters (pyboy 2.4.0, torch 2.5.0, gymnasium 0.29.1, numpy 2.1.2, sb3 2.3.2), and it
# additionally pins 12 nvidia-cu12 packages -- ~2.9 GB of CUDA -- which is wrong for a CPU
# contributor and impossible on arm64. Its pyboy pin has no aarch64 wheel at all and fails its
# Cython source build.
#
# 🔑 WHY THE VERSIONS ARE EXACT RATHER THAN >=:
#   * PyBoy save states are VERSION-LOCKED. A state written by a newer PyBoy will not load on an
#     older one ("Cannot load state from a newer version of PyBoy"). Ladder states are the whole
#     point of contributing, so a version drift silently makes a contribution worthless.
#   * A checkpoint's observation space must match the env that scores it, or SB3 refuses to load
#     it with "Observation spaces do not match". We have hit that twice with ONE game.
# Bump these only together with the server, never independently.

pyboy==2.5.4
stable_baselines3==2.9.0
gymnasium==1.3.0
numpy==2.5.2

# The env's own imports: skimage.transform.downscale_local_mean, matplotlib, mediapy, einops.
scikit-image==0.26.0
matplotlib==3.11.1
mediapy==1.2.7
einops==0.8.2

# ⚠️ torch is NOT pinned here on purpose -- it is installed in the Dockerfile from the CPU index
# (https://download.pytorch.org/whl/cpu). Installing it from PyPI drags the whole CUDA stack onto
# machines that cannot use it. Contributors do not need a GPU: this workload is emulator-bound,
# not matmul-bound, and the policy is ~2M parameters. Server runs torch 2.13.0+cpu.
