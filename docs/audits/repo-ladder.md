- **`make_ladder.py:215–231` — Untrusted sidecars forge progress and bypass the per-stage cap.** Upload distinct early-game states with sidecars containing `{"stage": 1001}`, `{"stage": 1002}`, etc. Even with `--max-per-stage 1`, every state is installed under a different invented stage. Neither authenticity nor the valid stage range is checked, so strangers can flood the ladder with early-game positions labelled as advanced progress.

- **`make_ladder.py:195–200, 240–241` — The installed bytes can differ from the verified bytes.** If the source directory remains writable during import, an uploader can supply a valid stage-7 state, then replace its path after classification but before `copy2`. The replacement—an early-game state or an unreadable file—is installed as stage 7 without verification. Hashing, classification, and copying each reopen the path independently.

- **`make_ladder.py:236–241` — Gaps in sequence numbers cause existing states to be overwritten.** If stage 7 contains `stage_7_001.state` and `stage_7_003.state`, importing another stage-7 state computes `seq = 3`. `copy2` overwrites `stage_7_003.state`, permanently losing an existing demonstration.

- **`make_ladder.py:190–191, 231–245` — Concurrent importers can overwrite each other and violate the cap.** Two importers both see an empty stage with `--max-per-stage 1`. Both accept a candidate and write `stage_7_001.state`; the second overwrites the first. Both retain their own candidate’s digest as “installed.” If the first importer subsequently encounters the second candidate, it skips it because its local count says the stage is full, even though its original installation has already been lost. There is no lock or atomic reservation protecting the check and write.

- **`make_ladder.py:201–205, 247–251, 290–293` — An entirely failed import reports process success.** Given a source directory containing only a truncated state that raises during loading, the script counts it as unreadable, installs nothing, and still returns exit status `0`. An automated ingestion job using the exit status therefore treats rejected uploads as a successful import.
