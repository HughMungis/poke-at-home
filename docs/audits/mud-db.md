- **models.py:95–100, 123–126 — Saved roundtime is never restored.** Set `char.rt_until = time.monotonic() + 30`, call `save(char)`, then immediately reload the character. Although `roundtime_until` is written to SQLite, `load()` restores only stance and position; `rt_until` remains `0.0`. `busy_for()` returns zero, allowing immediate action and contradicting the stated crash-persistence guarantee.

- **db.py:317–330, 407–414 — A transaction can commit before its enclosing batch succeeds.** On a connection with no open transaction, run `with db.batch():`, call `seed_new_character("web:alice", "Alice")`, then raise `RuntimeError`. The batch never explicitly starts a database transaction, so the seed function's `SAVEPOINT` is outermost. Its `RELEASE` commits the character immediately. The subsequent batch rollback cannot remove it, violating command atomicity.

- **db.py:306–309, 407–414, 423–428 — Committing helpers destroy active transaction savepoints.** Outside a batch, execute `with db.transaction(): db.tkv_set("alice", "spell", "fire")`. `tkv_set()` commits the connection, persisting the write and removing the savepoint. On context exit, `RELEASE sp1` raises `sqlite3.OperationalError: no such savepoint: sp1`. If the body instead raises after that helper, rollback also fails and the supposedly atomic write remains committed.

- **models.py:114–126, 168–174; db.py:320–327 — Batch rollback leaves cached money changed, and autosave can persist the failed debit.** Start Alice with `100` silver in memory and SQLite. Inside `db.batch()`, call `spend_silver(char, 30)`, then raise an exception. SQLite rolls back to `100`, but `char.silver` remains `70`. A later `save(char)` writes `70` back to SQLite, permanently charging Alice for the failed command.

- **models.py:135–139 — A failed autosave loses the character's dirty marker.** Mark Alice dirty after changing her room, then call `flush({"alice": char})` while another SQLite connection holds the write lock beyond the busy timeout. `flush()` removes Alice from `_dirty` before `save()` raises `OperationalError`. After the lock clears, subsequent flushes do not retry Alice unless another change marks her dirty; a process crash before another save loses the pending room change.
