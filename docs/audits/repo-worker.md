- **worker.py:244–248 — Server-controlled `job_id` permits arbitrary JSON-file overwrite.** With `CONTRIB_SPOOL=/app/unsent`, a job whose `job_id` is `../config` writes `/app/config.json`; an absolute ID such as `/home/user/settings` writes `/home/user/settings.json`. After evaluation, `os.replace()` overwrites the target without confirmation, destroying any existing contents wherever the worker has write access.

- **worker.py:272–276 — Recoverable authorization failures permanently delete completed work.** If the token expires or the server temporarily returns HTTP 401 or 403, `_flush_spool()` deletes each affected result. For example, three saved hour-long evaluations are all discarded during an authentication outage, although correcting the token would allow submission.

- **worker.py:181–182, 214 — A hostile response can exhaust memory or hold the worker indefinitely.** Every response is read completely into memory with no size limit. A checkpoint endpoint streaming gigabytes can kill the process through memory exhaustion. Alternatively, sending another byte every second without ending the response keeps the read active beyond the nominal 600-second socket timeout; the loop never resumes, and the first termination signal only sets `_STOP`, which this read does not check.

- **worker.py:225–228 — The checkpoint cache is not actually bounded.** Downloads accept arbitrary checkpoint filenames, but eviction counts only names ending in `.zip`. A server returning valid checkpoint archives named `model-0001.bin`, `model-0002.bin`, and so on leaves every download on disk. At the documented approximately 14 MB each, 1,000 such jobs retain approximately 14 GB despite `CACHE_KEEP = 3`.

- **worker.py:342–352 — Malformed server jobs crash the unattended loop outside its exception handler.** A successful JSON response of `{"job":{"checkpoint":"model.zip","seed":1,"steps":"oops"}}` raises `ValueError` while formatting the status message. The handler starts at line 354, so the process exits instead of rejecting the job and retrying. A top-level JSON array likewise crashes at `r.get("job")`.

- **worker.py:246–248 — Spooling does not provide the claimed reboot durability.** Closing the file and renaming it do not force its contents or directory entry to persistent storage. If an evaluation finishes, `_spool()` returns, submission fails, and the machine loses power before filesystem writeback, the completed result can disappear or return as an empty file. On restart, lines 264–266 delete an unreadable result, permanently losing the computation despite the promise at lines 237–241.
