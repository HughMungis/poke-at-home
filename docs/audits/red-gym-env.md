- **`red_gym_env_v2.py:981–988` — Healing reward is indefinitely farmable.** With unchanged party size, repeatedly take damage from full health to `0.5`, then heal to `1.0`. Each cycle adds `0.5² = 0.25` to `total_healing_rew`, paying `2.5 * reward_scale`. Taking damage never subtracts that reward, so the same recovery pays on every repetition without further progress.

- **`red_gym_env_v2.py:816–817, 912–923` — Required events ratchet the count, not individual achievements.** Starting with no required flags, set flag A: the maximum becomes `1`. Let the game clear A after its scene, then set a different required flag B: the count returns to `1`, so B pays nothing. This contradicts the claim that each flag latches once and also prevents swarm publication for that new achievement. On a resumed save containing A, clearing A and obtaining B instead leaves the baselined count at `0`.

- **`red_gym_env_v2.py:324, 802–810` — Excluded event flags already present in a save are subtracted twice.** Suppose the reset state contains `100` set flags, including one excluded flag. After earning one new non-excluded flag, the calculation is `101 - 100 - 1 = 0`, so the achievement receives no generic-event reward. The initial popcount already canceled the excluded flag; subtracting its current count again creates an extra reward threshold.

- **`red_gym_env_v2.py:418–422, 955–958` — Map-progress rewards arrive one action late and disappear at episode end.** With `base_map_progress = 0`, `max_map_progress = 4`, and both weights equal to `1`, an action entering rank `5` computes its reward using rank `4`; only afterward does it update the maximum. The next action receives the extra point. If entry happens on the final allowed step, that point is never returned before reset clears the maximum.

- **`red_gym_env_v2.py:874–876, 916–921` — A resumed initial save publishes incorrectly numbered swarm stages.** With an empty swarm directory and `init_state` containing eight required flags, reset leaves `swarm_loaded_stage = 0` and sets `base_required_flags = 8`. Obtaining a ninth flag produces `cur = 1` and publishes `stage_1.state`, despite the comment promising an absolute stage. Subsequent workers inherit the incorrect numbering, and frontier selection compares it against correctly numbered states as though it represented earlier progress.

- **`red_gym_env_v2.py:397–398, 428, 485–518, 761–764` — Video writers remain open when an episode finishes.** Set `save_video=True`, complete an episode, and close the environment without starting another episode. The only end-of-episode writer cleanup is inside `save_and_print_info()`, whose call is commented out; this class also supplies no `close()` cleanup. - **`red_gym_env_v2.py:452–459, 520–529` — Non-fast video recording writes no frames.** With `save_video=True` and `fast_video=False`, the first step opens three video writers, but the sole call to `add_video_frame()` requires `fast_video=True`.
