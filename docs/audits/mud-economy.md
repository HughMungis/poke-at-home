- **`shops.py:169–175` — Concurrent withdrawals can overdraw the bank.** With a balance of 100, two withdrawals of 100 can both read `have = 100` before either updates it. Each subtracts 100 and returns 100, leaving a balance of −100 and authorizing 200 in payouts against 100 deposited. The balance check and debit are not atomic, contradicting “Never overdraws.”

- **`craft.py:163–168, 173–182` — Brewing can create two potions from one set of ingredients.** Two draught attempts can both read the same single bitterroot and single stillwater. The first destroys both herbs; the second’s guarded destroys fail, but their results are ignored. If both success rolls are `0.0`, both attempts mint a potion despite only one recipe’s ingredients being consumed. The recheck does not close the gap described in the comments.

- **`craft.py:191–205` — Drinking applies effects even when consuming the potion fails.** Two calls using the same healing-draught row can run sequentially: the first destroys it and heals 25; the second fails to destroy the already deleted item but still heals another 25. Starting at 10/100 HP, the character reaches 60 HP from one potion. The ignored destruction result also allows a stale row to grant an effect after the potion has moved elsewhere.

- **`craft.py:238–249` — Forging does not enforce its documented maximum.** Pass an item with `plus = 5` and a success roll of `0.0`: the function writes `plus = 6` and returns `(True, 6)`. Repeating with refreshed rows permits further increases. `FORGE_MAX_PLUS` is never checked, contradicting the explicit claim that this operation is bounded.

- **`craft.py:103–109` — Concurrent gathering can consume the same patch use multiple times.** With stored state `"3:1000"` and `now = 1001`, two calls can both read one remaining use before either writes. Both write `"4:1001"` and return `True`. With successful forage rolls, two herbs are awarded from the final single use; additional overlapping calls multiply the excess yield.
