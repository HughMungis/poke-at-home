- **server.py:482–489; mudhttp.py:49–57, 120 — All clients behind Caddy share one authentication throttle.** `req.peer` is the TCP peer address, so requests forwarded by the local Caddy instance all use the same loopback address. One attacker submits 10 invalid `/mud/api/login` requests; another user's correct login, signup, or link verification then receives HTTP 429 for up to 300 seconds.

- **server.py:461–465, 499–505 — Valid non-object JSON crashes request handling and bypasses connection cleanup.** POST `/mud/api/login` with body `[]` or `null`: JSON parsing succeeds, but `body.get(...)` raises `AttributeError`. `handle()` catches only `HTTPError` here and has no enclosing cleanup `finally`, so it sends no response and never explicitly closes the writer. The same defect affects the other JSON endpoints. Connection disposal is left to garbage collection rather than guaranteed cleanup.

- **server.py:550–561 — A writer timeout skips socket closure during WebSocket cleanup.** If `wtask` remains pending—for example, because a client stops reading and the writer is blocked by backpressure—`await asyncio.wait_for(wtask, 3)` raises `TimeoutError`. Execution never reaches `writer.close()`. A failed writer task awaited here likewise bypasses closure, leaving transport cleanup dependent on other code or garbage collection precisely when the connection is unhealthy.

- **tick.py:176–196 — An idle client can be disconnected without ever receiving a ping, contradicting the stated liveness rule.** Suppose a session's last input and pong are at time `t`, then the process is suspended until `t + ws.PONG_TIMEOUT + 1` before its first idle ping. On resumption, `_ping()` closes the session immediately because both timestamps are old; it never checks whether a ping was sent. A sufficiently long process pause therefore disconnects healthy clients instead of giving them a chance to answer.

- **server.py:507–510 — HEAD responses discard the actual status and headers.** `HEAD /mud` produces a redirect in `route()`, but `handle()` replaces it with `200 OK`, no `Location`, and `Content-Length: 0`. Likewise, `HEAD /mud/play` loses the GET response's content type, cache policy, and actual content length. Clients checking redirects or resource metadata through HEAD receive incorrect results.
