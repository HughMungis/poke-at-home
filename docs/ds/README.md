## How to read this critically

These documents were generated by an LLM using this repository’s real source as the intended reference. They have not been verified against a running DS emulator. The feasibility document reports that its repository reads failed; the reads for this index also failed, so `docs/DISTRIBUTED.md` could not be checked. This is not a completed source audit.

Check these claims first:

- ~~**Throughput**~~ **— SETTLED, and the estimates were optimistic.** Measured on the two-core ARM target: **1.06x realtime with observation** (63.3 fps), against 2266 fps / 38x for the Game Boy env. The 2x and 5x DS examples in these documents are calculations and were **too high**. See [08-MEASURED.md](08-MEASURED.md).
- **Backend support — PARTLY SETTLED.** py-desmume 0.0.9 installs and runs headless on aarch64; frame stepping, the `(384, 256, 4)` stacked-screen framebuffer, memory reads and save/load all work (70 ms save / 139 ms load). ⚠️ **Input does NOT work via the obvious API** — see the keypad bug in [08-MEASURED.md](08-MEASURED.md). Worker isolation is still unverified.
- **RAM interpretation — still open, but probed once.** The anchor pointer is live and stable on the real ROM from frame 180; it has **not** been verified against real save data. This caution was correct and is restated in [08-MEASURED.md](08-MEASURED.md), including why brute-force searching cannot establish ownership.
- **Observation cost:** the 4.27× pixel ratio compares native screens. It does not measure this project’s preprocessing, training memory, or sample throughput.
- **Repository fit:** trace the actual PyBoy dependencies, reset behavior, observation shapes, and worker assumptions before treating the proposed seam as sufficient.
- **Task coverage:** verify that the chosen controls, screens, and progression signals cover the whole initial task. A public decompilation does not establish that those signals are ready to use.

**Read [08-MEASURED.md](08-MEASURED.md) first, then the feasibility document.** A decision to build needs measured throughput and validated instrumentation for one ROM revision. **Throughput now exists and is the reason to be cautious; instrumentation does not yet.** Reproduce the numbers with `tools/bench_desmume.py --rom <your.nds>`.
